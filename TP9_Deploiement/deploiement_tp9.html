1. Objet et méthode

Installer l'application sur un second poste, avec un compte SQL à droits limités, puis prouver qu'une sauvegarde est réutilisable. Le second poste est un clone Git réel du dépôt (git clone local, commit 4179d8c, 170 fichiers, clone propre), installé en suivant uniquement son README. Le serveur MySQL est une instance isolée (socket /tmp/opencode/mysql_tp9/run/mysql.sock, port 3309), afin de ne pas toucher la base principale. Chaque étape est rejouée et sa sortie est conservée dans preuves/.

3. Compte SQL à droits limités

CREATE USER 'tp9_app'@'localhost' IDENTIFIED BY 'Tp9Demo!2026';
GRANT SELECT, INSERT, UPDATE, DELETE ON tp3_conventions.* TO 'tp9_app'@'localhost';

Aucun privilège DROP, CREATE, ALTER, GRANT ni FILE : le compte lit et modifie les données, jamais le schéma. Deux refus ont été provoqués volontairement :

Commande exécutéeRéponseEffet constaté
DROP TABLE historiqueERROR 1142 (42000)table conservée, 9 lignes
CREATE TABLE essaiERROR 1142 (42000)aucune table créée

Après ces refus, la table historique est intacte et contient toujours 9 lignes. Preuve : preuves/compte_sql.txt.

4. Sauvegarde

mysqldump -u root --socket=… --single-transaction --routines --triggers tp3_conventions > preuves/tp3_conventions.sql

Code de sortie 0. Le fichier produit mesure 23961 octets (467 lignes) et porte l'empreinte SHA-256 a67aacad019f174a9cd58133bb4502c3a14fc4c17fac9ea2a134ce9ca4d37182. --single-transaction donne un instantané cohérent sans bloquer les écritures ; --routines et --triggers conservent les objets de programmation. Preuve : preuves/sauvegarde.txt.

6. Incident INC-001 et correction

ChampValeur
Symptôme/api/sante répond 503 ; journal PHP : SQLSTATE[HY000] [2002] No such file or directory
CauseDB_SOCKET recopié d'un ancien poste : le fichier socket n'existe plus et le socket est prioritaire sur host/port
Reproductionrenseigner un socket absent, démarrer le serveur, appeler /api/sante : 503 à chaque essai (3/3)
Correctiontest -S sur le socket réel, puis sed sur DB_SOCKET ; /api/sante repasse à 200 sans modifier le code
Préventionsocket documenté dans .env.example, contrôle test -S avant démarrage, santé vérifiée après installation

Le ticket complet, avec les étapes de reproduction, les réponses attendues et observées et les preuves, est dans ticket_incident.md. La reproduction et la correction sont rejouées dans preuves/incident_reproduction.txt.

8. Conclusion

L'installation est reproductible : huit étapes, un compte dédié, une santé à 200. Les droits du compte sont prouvés par deux refus 1142. La sauvegarde est datée, mesurée et empreintée ; sa restauration rétablit 9/9 tables après une perte volontaire. L'incident réseau est reproduit, expliqué et corrigé par la configuration, sans changement de code. Les quatre manques du README sont comblés : le déploiement peut être refait sur un poste vierge avec le seul README.
